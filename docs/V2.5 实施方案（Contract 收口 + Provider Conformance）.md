# V2.5 实施方案（Contract 收口 + Provider Conformance）v2

> **V2.5 不是新版本，是 V2 的最后一个阶段。它不加任何新功能，只做两件事：**
>
> 1. 把 V2 遗留的 Contract 收口（`ToolResult` ownership、生命周期、异常模型、取消语义）
> 2. 用真实 Provider 验证 V2 Contract 是否成立
>
> **V2.5 通过后，才有资格进入 V3 Contract Freeze。**

本版本采纳评审的 6 项修改（3 项 Contract 级 + 3 项 Conformance 方法学）+ 若干证据字段补全。

---

## 〇、V2.5 的定位

```text
V1   ──►  Architecture Proof    Kernel 边界成立
V2   ──►  Evolution Proof       加 Executor + Streaming，Kernel 不膨胀
V2.5 ──►  Contract Proof        Contract 收口 + 真机验证   ← 本文件
V3   ──►  Capability Expansion  只有在 V2.5 通过后，才能启动
```

**V2.5 的判据只有一条**：

> **V2 冻结的所有 Protocol / dataclass / 事件 / 异常语义，在真实 Provider 下行为符合预期。**

V2.5 真正产出的不是代码，而是**证据**。

## 二、Contract 收口

### 2.1 `ToolExecutor` Protocol 修正（P0-1）

**V2 现状（问题）**：

```python
class ToolExecutor(Protocol):
    async def execute(self, ctx, action) -> list[ToolResult]: ...
    async def execute_one(self, ctx, call) -> ToolResult: ...   # ← 移除
    async def close(self) -> None: ...
```

**问题**：`execute_one()` 是实现原语，不是外部契约。把它放进 Protocol 会：

1. 强制所有 Executor 实现理解这个内部原语
2. 让"Retry 语义"归属模糊（谁负责 per-call 重试？）
3. 与微内核哲学冲突（实现便利 → 公共契约）

**V2.5 冻结**：

```python
@runtime_checkable
class ToolExecutor(Protocol):
    """Tool 执行策略协议。

    生命周期契约：
      - Toolbox 归 Runtime 拥有；Executor 只借用，不负责关闭。
      - Executor.close() 只能关闭自己持有的资源。
      - Executor.close() 不得调用 Toolbox.close()。

    tool_call_id 契约：
      - 返回的每个 ToolResult.tool_call_id 必须等于输入 call.id。
      - 若 inner Tool 设置了错误值，Executor 负责覆盖。

    异常契约：
      - Tool.run() 内部异常 → ToolResult(error=True)，不冒泡。
      - Toolbox.lookup() 异常 → Executor infrastructure error，冒泡。
      - Executor 自身编程错误 → 冒泡。
      - asyncio.CancelledError → 穿透，不捕获，不转 ToolResult。
      - 单 call 超时 → ToolResult(error=True)。
      - 单 call 重试耗尽 → 保留最后一次 ToolResult(error=True)。

    execute() 是唯一公共执行入口。
    实现可自由选择内部是否使用 per-call 原语。
    """

    async def execute(
        self, ctx: RunContext, action: ToolCalls,
    ) -> list[ToolResult]: ...

    async def close(self) -> None: ...
```

**`execute_one()` 移入 builtin implementation**：

```python
# executor/builtin.py

async def dispatch(toolbox, call: ToolCall) -> ToolResult:
    """单一 ToolCall 的 dispatch 原语。内部 helper，不属于 Protocol。"""
    tool = await toolbox.lookup(call.name)     # 异常冒泡
    if tool is None:
        return ToolResult(
            tool_call_id=call.id,
            content=f"unknown tool: {call.name}",
            error=True,
        )
    try:
        result = await tool.run(call.arguments)
    except asyncio.CancelledError:
        raise
    except Exception as e:
        return ToolResult(
            tool_call_id=call.id,
            content=f"{type(e).__name__}: {e}",
            error=True,
        )
    result.tool_call_id = call.id
    return result
```

**影响**：`SequentialExecutor` / `ParallelExecutor` / `RetryExecutor` / `TimeoutExecutor` 内部使用 `dispatch()`，对外只暴露 `execute()`。

### 2.2 `Toolbox.lookup()` 异常语义统一（P0-2）

**V2 现状（不一致）**：Contract 说"lookup 异常 → ToolResult(error=True)"，但 `dispatch()` 的 `lookup()` 在 try 外。

**V2.5 冻结**：

```text
Tool 层：
  Tool.run() Exception        → ToolResult(error=True)
  Tool.run() CancelledError   → 穿透

Executor infrastructure：
  Toolbox.lookup() Exception  → 冒泡（不伪装成 ToolResult）
  Executor 编程错误            → 冒泡

Executor policy：
  单 call 超时                 → ToolResult(error=True)
  单 call 重试耗尽             → 保留最后一次 ToolResult(error=True)
```

**理由**：`Tool.run()` 失败是"用户工具执行失败"，属于 Agent 可观测的 Observation；`Toolbox.lookup()` 失败是"分发基础设施故障"（注册表损坏、MCP provider 挂掉），伪装成 ToolResult 会降低故障可观察性。

---

### 2.3 Cancellation 语义冻结（P0-3）

**V2 现状（冲突）**：同时写"`CancelledError` 穿透"和"Loop 捕获 `BaseException` → `TerminationReason.ERROR`"。`CancelledError` 是 `BaseException` 子类，字面冲突。

**V2.5 冻结**：

```python
# kernel/loop.py 的 except 分支

except asyncio.CancelledError:
    # 取消语义：cleanup + 重新抛出，不记为 ERROR
    raise

except Exception as exc:
    ctx.error = exc
    ctx.reason = TerminationReason.ERROR
    await runtime.events.emit("agent.error", ctx=ctx, error=exc)
    raise

finally:
    try:
        await runtime.finish(ctx)
    except Exception as e:
        if ctx.error is None:
            ctx.error = e
        await runtime.events.emit("agent.finish_error", ctx=ctx, error=e)
    finally:
        await runtime.events.emit("agent.end", ctx=ctx)
```

**规则**：

```text
CancelledError  → 不设置 ERROR，不设置 ctx.error
                  允许 finally 做 cleanup
                  重新抛出

Exception       → ctx.error = exc
                  ctx.reason = ERROR
                  emit agent.error
                  重新抛出
```

**`KeyboardInterrupt` / `SystemExit` / `GeneratorExit`**：**不做特殊处理，不进入 Agent 错误模型**。它们是进程级信号，不属于 Agent 语义。

**Loop 影响**：把 `except BaseException` 改为 `except asyncio.CancelledError` + `except Exception` 两个分支。**这是 V2.5 唯一允许修改 loop 的地方**，且行数不变或 +1（见 §九）。

### 2.4 `ToolResult` 收口

**V2 现状（问题）**：`ToolResult("hello")` 静默把 `"hello"` 存到 `tool_call_id`，`content` 为空。**不报错，不警告，语义错误。**

**V2.5 冻结**：

```python
@dataclass(slots=True, kw_only=True)
class ToolResult:
    tool_call_id: str = ""
    content: str = ""
    error: bool = False
    metadata: dict[str, Any] = field(default_factory=dict)
```

- `ToolResult("hello")` → **`TypeError`**（Python 3.10+ `kw_only=True` 保证）
- `ToolResult(content="hello")` → OK
- **不做 `__post_init__` 猜测**（数据类不猜调用者意图）

**范围限定**：V2.5 只对 `ToolResult` 应用 `kw_only=True`。**其他 dataclass 不动**。否则 Contract cleanup 会变成 API redesign。

---

### 2.5 `tool_call_id` ownership 冻结

**冻结为**：

```text
ToolCall.id  ──►  Executor  ──►  ToolResult.tool_call_id
                  （强制绑定，不是"为空补齐"）
```

- **Tool 不拥有 correlation identity**
- **Executor 强制覆盖**：`result.tool_call_id = call.id`
- Tool 若误填，静默覆盖（不做校验，工具没有理由填）

**理由**：如果采用"为空时补齐"，会允许 `ToolResult(tool_call_id="wrong-id")` 穿透，造成 `ToolCall A → ToolResult B` 这种难排查的错误。

**测试三态**（全部最终 `tool_call_id == originating_call.id`）：

```python
ToolResult(content="x")                                 # 空
ToolResult(tool_call_id="", content="x")                # 显式空
ToolResult(tool_call_id="another-call", content="x")    # 错误值
```

### 2.6 生命周期 docstring 补全

写入 `kernel/protocols.py`：

```text
生命周期所有权（V2.5 冻结）：

Runtime
  ├── owns Model
  ├── owns Toolbox
  ├── owns ContextEngine
  └── owns ToolExecutor

ToolExecutor
  ├── borrows Toolbox（只读使用，不负责关闭）
  └── owns 自身资源（HTTP client / sandbox / 子进程池）

关闭顺序：
  Runtime.close()
    ├── executor.close()     ← 只关自身资源
    └── toolbox.close()      ← 关闭所有 Provider
```

**测试**：`test_executor_close_does_not_close_the_toolbox`（用 `SpyToolbox` 断言 `toolbox.close_called == False`）。

### 2.7 Contract Freeze 流程升级

**V2 教训**：`StreamingModel.stream` 的类型标注 `async def` vs `def` 是文档错误。**Freeze 文档本身没有经过类型系统验证。**

**V2.5 起，流程升级为**：

```text
1. 写 Freeze 文档草稿
2. scratch.py —— 把所有 Protocol / dataclass / 类型别名抄进去
3. mypy --strict scratch.py && pyright scratch.py
4. 为每个 Protocol 写 minimal fake implementation
5. 用 fake impl 跑 contract tests
6. 修正文档
7. 正式 Freeze
```

**定位**：

> `scratch.py` 是 **Freeze snapshot，不是 canonical source**。

**防止漂移**：Contract test 验证 `current public signatures == freeze snapshot signatures`（比对 Protocol 方法名、参数、返回注解、dataclass 字段）。

**V2.5 具体动作**：为 V2 已冻结的所有 Protocol 补 `docs/freeze/v2/scratch.py`（只抄定义），跑 mypy，发现的类型问题登记 `CHANGELOG_v2_5.md`。

### 2.8 `agent_loop` 预算的正式立场

**V2.5 冻结**：

> **55 行是硬上限，不是性能指标。语义边界 > LOC 门禁。**

`loop.py` 只允许包含：

```text
iteration
reason
stop check
model.before / model.after
runtime.reason() / runtime.act()
termination reason assignment
finish error protection
CancelledError passthrough
```

**不得出现**：retry / timeout / stream / memory retrieval / tool dispatch / permission / budget / serialization。

V3 若需修改 loop，**必须先证明"这段逻辑属于 Control Flow"**，否则移出。

## 三、Provider Conformance Matrix

### 3.1 两层矩阵（Contract / Capability 分离）

```text
                    Contract      Capability
─────────────────────────────────────────────
Normal                  ✓
Tool                    ✓
Error                   ✓
Stream Text             ✓
Parallel Tool                         ✓
Stream Tool                           ✓
```

**Contract 层**：验证 Adapter 的核心契约，必须 `pass`。
**Capability 层**：验证 Provider 能力（可能受模型影响），允许 `pass` / `skipped_by_provider` / `model_did_not_trigger`。

### 3.2 Provider 分层

| Provider | 定位 | 门禁 |
|---|---|---|
| OpenAI | Primary Conformance | Contract 4 项必须 `pass` |
| Anthropic | Primary Conformance | Contract 4 项必须 `pass` |
| Ollama | Local / Compatibility | 尽力验证，不阻塞 |

### 3.3 场景定义

| 场景 | 层 | 输入 | Contract 判定 |
|---|---|---|---|
| **Normal** | Contract | `[user: "说你好"]`，无工具 | `Final(content=str)` |
| **Tool** | Contract | `[user: "北京天气"]` + `weather(city)` | `ToolCalls`，`call.name == "weather"`，`arguments` 可解析 |
| **Error** | Contract | 无效 model name | Adapter: SDK 异常原样传播；Agent: `reason == ERROR`, `error != None` |
| **Stream Text** | Contract | 同 Normal | `>= 1 TextDelta`；每个 `text: str`；`concat(delta.text) == assembled_text`；正常结束 |
| **Parallel Tool** | Capability | `[user: "北京和上海天气"]` + `weather(city)` | `ToolCalls` 或 `model_did_not_trigger` |
| **Stream Tool** | Capability | 同 Tool | 组装后 `ToolCalls` **结构一致**（name/arguments/id 正确），**不要求与非流式完全相等** |

### 3.4 Stream Text 的判定标准（P1-1）

**V2 现状（问题）**：

```text
累积 text == 非流式 Final.content
```

**问题**：LLM 非确定，同一 prompt 两次请求结果可能不同。跨请求相等不是 Streaming Contract。

**V2.5 冻结**：

```text
Stream Text Contract 只验证"流式自身的增量组装闭合"：

  ✓ 收到 >= 1 个 TextDelta
  ✓ 每个 TextDelta.text 是 str
  ✓ concat(delta.text) == adapter 组装出的 final text
  ✓ stream 正常结束（无悬挂 iterator）

非流式 vs 流式的相等性 → informational only，不参与 pass/fail
```

### 3.5 Stream Tool 的判定标准

**改为结构一致**：

```text
✓ 组装后的 ToolCalls 有正确的 name
✓ arguments 可解析为 dict
✓ id 非空
✓ （若多个 call）index 连续
```

**不要求**：`stream_result == non_stream_result`。

**Malformed Stream 的边界测试**：

```text
不属于 6 × 3 real-provider matrix。
作为 adapter-level unit contract，用 fake provider 验证：

  - args_delta 分片在 JSON 中间
  - args_delta 分片在 UTF-8 中间
  - 断流（stream 提前结束）
  - 多 call 交错
```

### 3.6 `contract_verified` 字段（P1-2）

**问题**：`skipped_by_provider` 和 `model_did_not_trigger` 不能证明 Contract。报告读者可能把 "6/6 scenarios" 误读为 "6/6 contract verified"。

**V2.5 冻结**：

```json
{
  "status": "model_did_not_trigger",
  "contract_verified": false
}
```

```json
{
  "status": "pass",
  "contract_verified": true
}
```

**规则**：

| status | contract_verified |
|---|---|
| `pass` | `true` |
| `skipped_by_provider` | `false` |
| `model_did_not_trigger` | `false` |
| `fail` | `false` |
| `not_verified`（无 API key） | `false` |

### 3.7 Provider Gate（P1-3）

**V2 现状（过宽）**：至少 1 个 Provider 全部通过。

**V2.5 冻结**：

```text
Gate A — Contract verification（必过）：

  OpenAI:
    ✓ Normal
    ✓ Tool
    ✓ Stream Text
    ✓ Error

  Anthropic:
    ✓ Normal
    ✓ Tool
    ✓ Stream Text
    ✓ Error

Gate B — Capability verification（尽力）：

  Parallel Tool    → pass / provider_limited / model_did_not_trigger
  Stream Tool      → pass / provider_limited / model_did_not_trigger

Gate C — Compatibility（Ollama，不阻塞）：

  至少 Normal + Error 真实运行
```

**Gate A 任何一项 fail，V2.5 不通过。**

**不得包含**：retry / timeout / normalization / runtime logic / markdown generation。

### 4.4 模型名不写死在 Contract

**通过环境变量配置**：

```bash
AGENTKIT_OPENAI_MODEL=...        # default: gpt-4o-mini
AGENTKIT_ANTHROPIC_MODEL=...     # default: claude-3-5-sonnet-latest
AGENTKIT_OLLAMA_MODEL=...        # default: qwen2.5:7b

```

**理由**：Contract 不依赖具体模型；报告依赖具体模型。

### 4.5 Error 场景分两层

**Adapter-level**：

```text
SDK exception（如 NotFoundError）
    ↓
原样传播（不吞、不转 ToolResult）
```

**Agent-level**：

```text
Model error
    ↓
agent_loop 捕获 Exception
    ↓
ctx.reason == ERROR
ctx.error != None
exception re-raised
```

**两者都测**。后者才是 V2 Contract。

### 4.6 降级策略

| 情况 | 行为 | contract_verified |
|---|---|---|
| 环境变量缺失 | 该 Provider 全部标 `not_verified` | `false` |
| Provider 不支持该能力 | `skipped_by_provider` | `false` |
| 模型未触发期望行为 | `model_did_not_trigger` | `false` |
| Contract 违反 | `fail` | `false` |
| 场景通过 | `pass` | `true` |

**关键区分**：V2.5 验证 **Contract 是否成立**，不是 **Provider 是否总能触发某个行为**。

## 九、Loop 的 V2.5 变更明细

**V2.5 唯一允许的 loop 改动**：`except` 分支拆分。

**V2 现状**：

```python
except BaseException as e:
    ctx.error = e
    ctx.done = True
    await runtime.events.emit("agent.error", ctx=ctx, error=e)
    raise
```

**V2.5 改为**：

```python
except asyncio.CancelledError:
    raise

except Exception as e:
    ctx.error = e
    ctx.done = True
    ctx.reason = TerminationReason.ERROR
    await runtime.events.emit("agent.error", ctx=ctx, error=e)
    raise
```

**行数影响**：+1 行（净增 `except asyncio.CancelledError: raise` 两行，删除 `except BaseException` 一行）。

**预计 `agent_loop` 51 行**（预算 55）。

**必须同步更新**：`test_contract_v2.py` 中的 loop 行数断言（从 50 → ≤55），保持 ≤55 门禁。
