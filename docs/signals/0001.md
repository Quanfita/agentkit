# Signal 0001

- **Date**: 2026-09-19
- **Trigger**: 为已登记缺口 G2（I4 × 批内停止）做真机复现：`SequentialExecutor` + `DenyListPolicy({"write_file"})`
  + `RetryExecutor`，真实 DeepSeek `deepseek-flash`，任务要求"在一次 assistant turn 里并行发出两个工具调用"；
  另跑一次 `CostTracker(budget=1)` 触发预算耗尽。
- **Expected**: 看到"部分批次" —— `assistant(tool_calls=[A,B])` 只写出 1 个 tool 结果（缺口 G2 描述的形状）。
- **Actual**: 两条真实路径都**没有**产出部分批次。
    - 权限拒绝路径：`assistant` 声明 2 个调用，history 里 **2 个** tool 结果（`call_00_…`、`call_01_…`
      逐一对上；被拒的那个是 `metadata["error_class"]="policy_denied"` 的 error 结果）。
      命中原因：`PermissionExecutor` 拒绝时返回 `blocked_result()`（非 `None`），
      `execute_serial()` 因此不中断，整批走完。
    - 预算耗尽路径：`CostTracker` 在 **`model.before`** 置位 `ctx.stop`，
      由 Loop 检查点 1 停下 —— 模型调用次数 0，history 形状 `[('user', 0, None)]`（无 `tool_calls`），
      `reason=stopped`。整批请求根本没有发出，history 合法。
    - 隔离实验（不经过 Loop，直接 `model.generate()`）：把"声明 2 个 tool_call 只回 1 个结果"的 history
      交给 DeepSeek → **400**：`An assistant message with 'tool_calls' must be followed by tool messages
      responding to each 'tool_call_id'. (insufficient tool messages following tool_calls message)`。
      同形状但两个结果都在的对照载荷 → 接受（见 Signal 0002 的矩阵）。
- **Reproduction**:
  ```bash
  # ① 权限拒绝路径（期望部分批次，实际批次完整）
  python - <<'PY'
  import asyncio, os, sys, tempfile, pathlib
  sys.path.insert(0, ".")
  from agentkit.kernel.loop import agent_loop
  from agentkit.kernel.state import RunContext
  from agentkit.kernel.types import Message
  from agentkit.toolbox import Toolbox
  from agentkit.contrib.local_tools import make_local_tools
  from agentkit.executor.builtin import SequentialExecutor
  from agentkit.executor.permission import PermissionExecutor, DenyListPolicy
  from agentkit.executor.retry import RetryExecutor
  from agentkit.context.engine import ContextEngine
  from agentkit.context.providers import SystemPrompt
  from agentkit.runtime.default import DefaultRuntime
  from agentkit.models.openai import OpenAIModel

  async def main():
      d = pathlib.Path(tempfile.mkdtemp()); (d/"a.txt").write_text("hello", encoding="utf-8")
      tb = Toolbox(make_local_tools(d))
      ex = RetryExecutor(PermissionExecutor(SequentialExecutor(tb), DenyListPolicy({"write_file"})))
      m = OpenAIModel("deepseek-flash", base_url="https://api.deepseek.com",
                      api_key=os.environ["DEEPSEEK_API_KEY"])
      rt = DefaultRuntime(model=m, toolbox=tb,
                          context=ContextEngine(providers=[SystemPrompt(
                              "Issue BOTH tool calls in the SAME assistant turn, in the given order.")]),
                          executor=ex)
      t = ("请在一次 assistant turn 里并行发出两个工具调用,顺序必须是:"
           "① write_file(path='x.txt', content='hi') ② list_dir(path='.')")
      ctx = RunContext(task=t, system=t, messages=[Message(role="user", content=t)], max_iterations=3)
      await agent_loop(rt, ctx)
      print("声明:", [c.id for mm in ctx.messages if mm.role=="assistant" and mm.tool_calls for c in mm.tool_calls])
      print("结果:", [mm.tool_call_id for mm in ctx.messages if mm.role=="tool"])
      await rt.close()
  asyncio.run(main())
  PY
  ```
- **Severity**:
    - [ ] S1 = 无法完成用户任务
    - [ ] S2 = 完成了但方式意外
    - [x] S3 = 完成但体验不佳（三个真实任务都跑完了；本条记录的是缺口 G2 的**后果边界**）
- **Architectural implication**:
    - 现有三个防线（Firewall / ABI Freeze / Conformance）能否拦住？
        Firewall 无关；ABI Freeze 只冻结类型形状，history 内容不合法不属于 ABI 形状问题；
        Conformance 只走合法路径（6 台设备全部不触发批内停止），拦不住。
    - 拦不住的，它落在哪一层？
        - [ ] Kernel（罕见）
        - [ ] Runtime / Harness
        - [x] Context / Executor / Provider
        - [ ] 实现 bug
    - 初步判断（不做归类，只描述现象）：批内停止的**唯一仓库内触发点**是 `CostTracker`（`model.before`），
      它停在 act 之前；`PermissionExecutor` 拒绝会写满整批。因此"部分批次"今天没有可达路径，
      但 `DefaultRuntime.observe()` 的 `zip(..., strict=False)` 保留了写出更少结果的能力
      （V3 §3.8 刻意行为，见 `docs/INVARIANTS.md` 缺口 G2）。
